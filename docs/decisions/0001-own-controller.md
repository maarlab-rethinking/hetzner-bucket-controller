# ADR-0001: An own controller rather than ACK, Crossplane or COSI

**Status:** accepted, 2026-10-09

## Context

The platform keeps its backups (OpenBao Raft snapshots, CloudNativePG base backups and WAL) in
Hetzner Object Storage. Buckets were created by imperative `ensure-bucket` Jobs (`aws-cli` run as an
Argo CD `PostSync` hook) that:

1. `head-bucket`, and if missing `create-bucket --object-lock-enabled-for-bucket` with
   `LocationConstraint=<location>`;
2. re-PUT the default Object Lock retention (`COMPLIANCE`, 30 days) on every run;
3. re-PUT a lifecycle configuration (expire current versions after 35 days, noncurrent versions
   after 5 days, drop expired delete markers).

That only runs when Argo CD syncs the Application, so drift made outside the cluster (someone
editing the lifecycle in the console, a bucket deleted by hand) stays unnoticed until the next sync.
A pre-existing bucket without Object Lock is reported as "already exists" and the following
`put-object-lock-configuration` fails the Job, with nothing on the cluster side explaining why. We
want the bucket to be a declarative resource, reconciled continuously, with its failure modes
surfaced as status.

Two facts constrain any option:

- Hetzner has no API to create S3 credentials. They are generated by hand in the Console, per
  Hetzner project, and grant full access to every bucket of that project (no IAM, no per-bucket
  scope). Whatever manages buckets can only **consume** an existing credential
  ([ADR-0005](0005-credentials-read-per-namespace.md)).
- A bucket does not have to exist before its consumers: a backup to a missing bucket fails and
  retries until it appears. Creating buckets from inside the management cluster, after it is up, is
  therefore fine; there is no need for an out-of-cluster tool such as OpenTofu.

## Options considered

**ACK `s3-controller`.** AWS's own controller. It can be pointed at a custom endpoint, but reading a
`Bucket` calls about twenty bucket sub-resource APIs (`GetBucketAccelerateConfiguration`,
`ListBucketAnalyticsConfigurations`, `ListBucketInventoryConfigurations`, `GetBucketLogging`,
`ListBucketMetricsConfigurations`, `GetBucketNotificationConfiguration`, `GetBucketRequestPayment`,
`GetBucketTagging`, ...). Hetzner explicitly does not support most of them
([ADR-0002](0002-model-only-what-hetzner-documents.md)), and the controller tolerates "unsupported"
errors only for ABAC and accelerate: any other error aborts the read, so the resource would never
become synced. It also brings the AWS-specific model (ARNs in the `aws` partition, IAM-oriented
fields). Rejected: incompatible.

**Crossplane** (`provider-upjet-aws` S3, or a MinIO provider). `provider-upjet-aws` wraps the
Terraform AWS provider; endpoint overrides exist, but the refresh of `aws_s3_bucket` also reads
sub-resources Hetzner does not implement, and whether each of those errors is tolerated depends on
the Terraform provider version — a compatibility we would be borrowing, not owning. It would also
introduce Crossplane core plus a provider family into a platform that is Argo CD-only today, for a
single resource type. The community MinIO providers do not model Object Lock or lifecycle at all
(`provider-minio`'s `Bucket` has name, region, deletion policy and policy only). Rejected:
disproportionate dependency, and Object Lock and lifecycle not covered.

**COSI** (Container Object Storage Interface). The Kubernetes SIG Storage API for buckets. The
current API (`v1alpha2`) is pre-release, the project publishes no generic S3 driver, and the API
models bucket provisioning plus access-credential minting — the latter is exactly what Hetzner
cannot do. Object Lock and lifecycle are outside its model. Rejected: immature, and the wrong
abstraction for a provider without a credentials API.

## Decision

A small controller with one namespaced CRD, `Bucket` (`objectstorage.maarlab.dev/v1alpha1`), using
`aws-sdk-go-v2` against the Hetzner endpoint. It calls only the APIs Hetzner supports, models only
what Hetzner documents, and encodes the Hetzner-specific constraints (create-time Object Lock,
location-bound region, global names) as validation and status conditions. Same layout and tooling
as `hcloud-egress-gateway-controller`.

## Consequences

- The `ensure-bucket` Jobs and their aws-cli image disappear from the platform; each bucket becomes
  a `Bucket` object next to the `ExternalSecret` that provides its credential.
- The controller holds a full-access credential for every Hetzner project it manages buckets in, as
  the Jobs did. It must run in the management cluster only.
- Compatibility with Hetzner is ours to keep: a change on Hetzner's side shows up as `ProviderError`
  on every `Bucket`, and the fix is in this repository.
